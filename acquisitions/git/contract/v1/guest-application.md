# Applying a Git delivery in the jail

`acquisitions/git/jail/application.py` verifies the uploaded artifact against the `ready` response (size, SHA-256 and format). It imports the bundle into an empty bare repository using local Git and explicit branch and tag refspecs. A bundle that needs objects from another repository cannot be applied. The empty-repository marker is handled separately.

**Clone:** prepare a private working clone without hardlinks in a new private directory (`.agentbox-clone-*`, 0700) beside the destination, so publication is one rename within the destination's directory, whichever filesystem holds the delivery. Check the selected branch or tag, configure its public origin, and check out before publishing. Publish only to an absent destination or the same empty directory, then remove that private directory; a failure leaves it. An empty repository starts with an unborn `main`.

The destination's parents, and a fetch's or pull's working repository's, must be directories of root or this user, not other-writable, except a sticky one (such as `/tmp`, where pip clones): another user cannot rename or remove what this user puts there. The destination itself, the working repository, any directory between it and the starting directory, and the upload directory have no such exception; nor does a symlink.

**Fetch:** resolve the named remote inside the jail. Check the existing repository, configuration, tags and refspecs before updating it from the delivered local repository. Fetch does not rewrite the remote URL, local branches, index or worktree. Updating refs and writing `FETCH_HEAD` is not one transaction; failure or cancellation can leave changes. There is no automatic retry or rollback.

**Pull:** the same checks as a fetch, also accepting `pull.ff` and `pull.rebase` in the repository's configuration and refusing any `filter.*`; the plan is a precondition only. Stock `git pull [FLAG]` then runs in the working repository, in its own process group:

```text
git -c remote.R.vcs=agentbox pull --> git fetch --> git-remote-agentbox R URL --> git upload-pack <verified staging>
```

The helper (`pull.py`, staged with the delivery, the pull's only `PATH` entry besides `/usr/bin:/bin`) serves only the resolved remote and its configured URL, by `connect git-upload-pack`, as often as Git asks; `GIT_ALLOW_PROTOCOL=agentbox` admits no other transport. `FETCH_HEAD`, merge messages and history name that URL, never the staging. The environment is hardened as for a fetch: no system or global configuration, hooks, editor, credentials, submodule recursion, autostash or automatic maintenance. Command-scoped configuration adds only the effective `user.name`, `user.email`, `pull.ff`, `pull.rebase` and `branch.<current>.rebase`: the repository's value, else the jail user's global one (includes followed, read outside any repository). A rebase mode other than a boolean, or `pull.ff` other than a boolean or `only`, refuses before the request. Not imported: identities set only in the environment (`GIT_AUTHOR_*`, `GIT_COMMITTER_*`, `EMAIL`) and conditional global includes (`includeIf`), which match no repository there; Git then uses its own fallback identity or fails.

Git's output streams through without a thread or blocking write, and without changing the shim's shared descriptor flags (pipes and terminals are reopened privately); output not written within 2 s of Git's end is dropped, as is a report line not written within 2 s, so an unread stderr cannot hold the shim. Its exit status is the pull's: a refused fast-forward, divergence without a strategy, local changes in the way or a conflict leave Git's own state (`MERGE_HEAD`, `rebase-merge/`), with no reset or retry; the result is `failed`, `changes: possible`. A normal exit with both output pipes at EOF removes the staging; that observes the direct child and its pipes, not every descendant. Cancellation signals the group; the group is signalled only while its leader is unreaped. An abnormal end, cancellation included, keeps the staging. A pull's tracking refs follow stock fetch (tag auto-follow), not the fetch plan; a pull during an unfinished merge spends its request before Git refuses. The path checks are a fetch's: a clone beneath sticky `/tmp` can be fetched and pulled.

Local Git runs without a shell or network fallback. These are checks on the guest's result, not protection against a malicious process in the same jail. The application reports whether working-repository changes are possible and whether its own cleanup was observed. Neither is a host settlement or durability claim.
